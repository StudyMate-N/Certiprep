# Private file-mirror maintenance

Use the Supabase skill and the existing administrative connector. Keep all file operations in bucket `cpa-verified-library` and the dedicated CPA transfer function. No public read/write policies are needed. The catalogue remains private in `cpa_library`.

1. Read current database asset SHA-256 values and storage totals. Select only new/changed approved files; do not re-upload or re-download stable verified works each hour. Put selected package paths in a JSON array.
2. Run `prepare_storage_transfer.py --root <extracted-library> --workdir <private-directory-outside-git> --paths-json <selected-paths.json> --verified-map-json <current-verified-object-map.json> --existing-total-bytes <live-total> --existing-cpa-bytes <live-cpa-total>`. For an empty first mirror, use --initial-mirror instead of the paths/map flags. Existing mirrors require a current verified map; identical verified files are skipped without duplicate capacity charges. Observed totals must be nonnegative. It verifies approved ownership, source bytes, hashes, paths and a 40 MB per-object cap. It stops above 800 MiB total observed storage or 500 MiB CPA storage. Report capacity choices; do not upgrade, delete or pause other applications.
3. Pass the prepared private deployment request to the connected Supabase Edge Function deployment tool. The helper creates a fresh 0700 private directory and an atomic 0600 key file. Its `verify_jwt=false` is deliberate: the body implements its own short-lived, high-entropy capability authentication before all privileged actions. The allowlist uses own-property checks; the server validates actual bucket privacy/limits before file writes and checks exact length, MIME and SHA-256 through an authenticated upload proxy. The bucket is fixed and existing objects cannot be overwritten, and server credentials stay in server environment variables. Never publish the capability or signed URLs.
4. Run `mirror_storage.py --root <extracted-library> --workdir <private-directory>`. It rejects unauthenticated requests, uploads approved files, downloads every selected hosted object, checks full SHA-256 and byte counts, and checks ordinary public access is denied. Do not mark hosted until every selected file passes.
5. Immediately replace the CPA transfer function with the disabled response `Deno.serve(() => new Response('Transfer closed', {status:403}));` using the administrative connector. Verify it returns 403 even with the former key; then remove the local temporary key. Do not change unrelated functions. Download URLs expire after 15 minutes and closure does not revoke those already issued. The current proxy protocol issues no signed upload URLs. The initial one-time mirror used private signed uploads valid for two hours; existing immutable objects cannot be overwritten and the signer was disabled. Signed URLs are transient and must never be stored as permanent source provenance.
6. Upsert verified object paths and hashes into `cpa_library.assets`, keep audit events, verify bucket object counts/bytes and privacy, then update hosting status, capabilities and the release ledger. Deliver attribution/adaptation notices with user-facing distributions. A private file mirror is not a public reading app.

The archive is an immutable dated snapshot. Later cloud-mirror status belongs in the current repository and database; do not silently change the checksum of an already delivered ZIP. Future substantive acquisitions create a tested replacement/version with a new exact checksum. Access to the private bucket uses supported administrative authorization and short-lived signed downloads; a failed/expired URL is not evidence that a resource was never acquired.

A prior verified map must be the contextual object report containing project_ref, bucket, public=false, all_objects_downloaded_and_sha256_verified=true and file-level exact object_path, bytes, SHA-256 and download_verified. Reject evidence from another project/bucket/address. An empty selected-path list is a clean no-op. Larger legitimate resources can stay in the verified archive with mirror status pending; the 40 MB hosting cap is not a reason to misclassify their academic quality or inflate counts with chunks.
