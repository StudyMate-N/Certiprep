# Quality-led success criteria and operating limits

Plan the first release around **120 substantial usable files**: Foundation 30; Intermediate 36; Advanced including specialisations 42; Practical/workshops 12. This is a coverage-planning target. Quantity never compensates for weak teaching, inaccurate answers, unclear rights or missing syllabus outcomes. Reassess the target openly if the confirmed syllabus justifies a change; never split files to meet it.

Count independent substantial works/complete practical resources once. Treat a textbook's separately stored chapters as one work. Count supporting images, metadata and duplicate formats as assets only. Count external access links separately. Report bytes, acquisition entries and grouped works distinctly.

A complete project requires the exact official syllabus/sitting/transition and cut-off to be locked; teaching plus useful worked practice for every examinable topic; current Kenyan authority where relevant; defensible rights for each hosted component; independent subject-expert review of each paper; and tested offline index, database, hashes and downloadable release. Official practical/workshop participation cannot be supplied by a reading library. A permission or academic-review gap is unresolved, even when an external link is useful.

Each hourly run is bounded to 40 minutes, 12 candidates, five approved resources and 150 MiB of acquisition, with a 50-minute non-overlap lease and no new charges. Reject a single response over 180 MiB. Prefer targeted source checks to repeated downloads of stable valid files. Remove unsuitable or duplicate items from approved distribution while retaining history. Stop a run on missing authorization, unrecoverable integrity failure or lease conflict; report the exact blocker and continue independent lawful work where possible.

Completion changes maintenance priorities; it does not stop monitoring. After a verified core release, focus on legal/standards/syllabus changes, broken access points, corrections and uncovered topics. The existing hourly automation remains enabled until the user changes it.
